# 普通用户写成一篇短文的续写验收

基线：main dece5562。用户要求从记录一条自己的想法到写成短文，发现卡点只作必要修复和减法，不新增面板或概念，浏览器验收及 review 无问题后停止。

实际走查已完成：空库新建随笔、写自己的观察、创建永久笔记、直接在正文中写观点/理由/边界、从一个问题开始写、现有材料列表确认加入、用默认正文编辑器写四段短文并保存。此路径无需 Key，也无需填写侧栏观点表单。

确认卡点：从文章的材料列表打开笔记，再点侧栏写作，当前文章被切回“主题”，材料弹层仍打开，并显示“先选择主题并生成提纲”的旧提示。正文还在，但用户需额外关闭弹层、切到草稿才能续写。

本次只修复返回行为：写作侧栏入口不强制重置当前标签，返回时收起临时材料弹层，删除强制提纲的提示。已有主题/提纲/草稿的选择保持；从零进入仍可新建主题；主动点击主题库仍能切换主题。

复用 app-rail-event-bindings 和 writing-related-notes-panel，不修改 prototype 入口文件或存储逻辑。不因现有编辑器样式 warning 扩大任务范围。
