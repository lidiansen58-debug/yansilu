# 产品 UX 反馈汇总与优化设计

更新：2026-08-30

## 反馈来源与任务

两轮测试均围绕真实任务：把读书随笔加工为可复用的当前观点，建立两条关联，并为后续主题写作准备材料。

第二次反馈表明，用户记住方法后能完成主链，速度也有所提高。这支持继续验证产品方向，但不足以证明普通用户能独立上手；效率提升主要来自用户自己记住流程。

## 用户报告的问题

### 立即修复的功能故障

1. 侧边栏栏目展开控件无响应，且没有空状态或失败反馈。
2. 卡片图片预览显示错误，无法核对图片内容。
3. 新建卡片无响应，既未创建内容，也没有成功或失败提示。
4. 安装包缺少版本、更新说明、帮助入口和已知问题说明。

以上是用户报告，不代表所有场景均已复现。功能故障与缺少状态反馈共同破坏信任；逐项验证结果见下文。

### 核心体验问题

1. **规则黑盒化**：笔记用途由目录推导，用户无法判断新建、移动或重新归类后会发生什么。
2. **名称误导**：用户把整理入口理解为“复习”；当前代码中的可见入口已是整理相关命名，未复现仍显示“复习”的情况。
3. **概念过载**：关系类型过多；“提纯”“桥接关系”“主题索引”等词要求用户先学方法，再能完成动作。
4. **检索不完整**：原有搜索不能找回尚未载入的正文；语义搜索没有可用入口和可解释结果。
5. **没有任务引导**：用户即使知道主链，也会在每一页犹豫下一步。Demo 更像资料库，不像可跟随的练习。
6. **快速记录不够轻**：记录前或记录后过早要求分类和理解结构，无法提供低负担的捕捉体验。

## 产品判断

研思录不应要求普通用户先理解卡片笔记法，才能体验它的价值。主路径应是具体动作，不是概念学习：

`记下来 -> 用自己的话整理 -> 保存当前观点 -> 说明必要关联 -> 组织可写主题 -> 写作`

“永久笔记”“主题索引”“桥接”等是高级方法名，不应成为初学者的首要导航。系统的存储目录、关系本体和 AI/索引实现也不应成为用户必须理解的规则。

## 设计方向（不等于本轮全部交付）

### 1. 记录时零门槛

- 首页与手机首屏唯一主操作是“记一条”。
- 保存即成功，不要求选择笔记类型、目录、关系或标签。
- 新内容统一进入“待整理”；用户以后决定是否加工或删除。

### 2. 整理时只有一个下一步

- 保持整理与间隔重复回顾的命名边界；当前整理入口不再额外改名。
- 每次只呈现一条内容和一个主要动作，例如“用自己的话整理”。
- 完成后，下一步改为“保存当前观点”或“先保留，稍后再处理”。
- 不把队列、候选、提纯等内部概念放在主界面。

### 3. 观点形成可见，但不强迫填写

- 当前观点是用户最终确认的可复用判断。
- “最初的问题”“为什么改变”“依据笔记”只在需要时展开，不是每次保存的必填仪式。
- 形成过程以可读结果展示：这条观点来自什么、为什么改、关联到哪里。

### 4. 关系默认简单，进阶能力延后

第一次建立关联只提供五种：

1. 有关
2. 支持这个观点
3. 提出不同看法
4. 补充条件
5. 提供例子

其余关系保留在“更多关系”中，且不改变既有数据和图谱能力。每条关系只要求一句“它怎样影响当前观点”。

### 5. 搜索先可靠，再智能

- 本轮提供本地标题、正文、标签、路径和 ID 的关键词检索。
- 结果展示命中片段和位置；支持 `Ctrl/Cmd + Shift + F`。
- 语义检索仅在具备模型/索引状态、明确入口、结果说明和降级提示后开放。
- 在此之前，不将底层框架描述为已可用功能。

### 6. Demo 变成练习，而不是资料库

Demo 首次进入只要求完成一个小闭环：

`看一条材料 -> 用自己的话写一句 -> 保存一个当前观点 -> 建一条有理由的关联`

主题与写作只在闭环完成后出现。每一步必须有可见结果和“下一步”按钮；用户不应通过翻阅大量示例猜流程。

## 分阶段方案

### 0. 稳定性修复：先恢复信任

- 修复侧边栏展开、新建卡片、图片预览。
- 对每个操作提供可见的成功、空状态和失败原因。
- 在“关于”或设置中显示版本号、更新说明、帮助入口和问题反馈入口。

验收：三项核心操作均可重复成功；失败时用户能知道原因和下一步；安装后可确认版本。

### 1. 基础可用性：搜索与命名

- 实现正文全文检索与全局入口。
- 核查当前整理命名，不为旧反馈重复改名。
- 取消对未完成语义搜索的产品承诺。

验收：可通过正文关键词找回尚未打开的笔记；首页给出当前主操作。大规模笔记库的检索耗时需要另做容量测试，不承诺固定 3 秒。

### 2. 主路径减法：记录、整理、关联

- 新建默认仅记录；目录分类退到后台。
- 移动笔记时区分“只改变位置”与“改变笔记用途”，并给出可理解确认。
- 关系默认缩减为五种，更多类型按需展开。
- 待整理页每次只有一个主动作。

验收：新用户 10 秒内能留下第一条记录；首次建立关联不需要理解桥接等术语。

### 3. 引导与高级能力

- 把 Demo 改为可跟随的四步练习。
- 让主题和写作只在已有观点与关联后出现。
- 设计并实现可用、可解释、可降级的语义搜索。

验收：未接触卡片笔记法的用户能独立完成一次“记录到当前观点再到关联”的闭环；语义搜索关闭或失败时，关键词搜索仍完整可用。

## 不应做的事

- 不靠增加更多帮助面板解决困惑。
- 不把 23 种关系类型全部重新命名后继续默认展示。
- 不为保留目录实现而让用户理解目录决定笔记身份。
- 不把间隔重复回顾混入“待整理”。若未来做回顾，应独立命名并定义节奏、范围和反馈。
- 不在稳定性问题未收口前扩展 AI、图谱或写作新功能。

## 本轮实现与验证结果

1. **新建记录**：复现首页首条记录入口漏传创建依赖；已修复。创建失败不再生成未落盘的假成功笔记，保留原编辑内容，显示错误原因；重复点击合并为一次创建。
2. **目录展开**：有内容目录可展开；空目录原来禁用展开，已改为可展开并显示空状态。
3. **图片预览**：复现含空格附件名重复编码导致读取失败；已修复，增加加载、错误和重试状态。浏览器验证图片实际解码成功。
4. **版本与帮助**：原有设置中已有版本及帮助，本轮提高入口可发现性，提供本机版本说明和可离线打开的独立帮助文件，并加入桌面资源配置。尚未重新打包验证原生安装目录。
5. **正文搜索**：新增全局入口及命中片段，覆盖未打开笔记；文件更新后缓存失效，部分文件无法读取时明确提示，不将其当作完整搜索结果。
6. **归类规则**：通过“归类与移动”明确选择随笔、文献或永久笔记目录，同步文件元数据与目录记录；有未保存内容时阻止移动。写入失败可回滚原文件与类型，已有附件和关系保留。
7. **关系选择**：常用类型收敛为五种，其余按需展开；已有高级类型不丢失。正文链接与外部关系同属已保存关系，修复总数重复计算及界面中的内部标记。
8. **主路径**：空库先写一条记录；已有任务按当前进度提供主操作，其余收起。未确认观点进入保存当前观点，不误导到写作。保留现有 Demo 练习路线，修复导入完成反馈，未另造强制四步向导。

验证覆盖：单元测试、API/文件落盘集成测试、真实浏览器点击流程，以及桌面与窄屏搜索布局、断网帮助、故障反馈、归类失败回滚。
