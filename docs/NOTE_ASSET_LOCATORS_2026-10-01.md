# 附件定位信息保留

分支：`fix/note-link-selection`，接续移动与导出的代码示例保护。

## 行为

- 移动笔记或导出时，嵌入附件只改文件路径，原样保留 `#标题`、`^区块`、显示别名、尺寸别名以及别名里的竖线。
- 普通 Markdown 附件的 `#page=2`、SVG 区域等定位信息与物理文件路径分开处理。附件扫描找到实际文件，重写后保留定位信息，避免导出将 `文件.pdf#page=2` 当成文件名而报缺失。
- 同一附件的多个定位引用只复制一个物理文件。尖括号路径、中文、空格和括号继续支持；代码和转义示例、外部 URL 与本页定位保持原文。

仅修改附件解析/重写模块，没有新增界面或改变笔记关系规则。

## 验证

- 92 项相关单元测试通过，覆盖附件、文章/Markdown 导出、目录生命周期、自动关联、Markdown 及导入。
- 2 项浏览器用例通过：新增实际目录菜单移动，验证落盘与刷新重开的定位信息；原有移动/删除流程回归。
- 临时笔记库的重命名/移动测试同时验证带定位的附件路径、旧标题笔记链接及独立关系保留。
- 真实附件导出测试验证只复制一次、文件内容一致、普通定位与嵌入标题/区块/自定义别名保留，代码里的缺失示例仍保持原文。
- 编码检查无新增问题，`git diff --check` 通过。

本轮按附件改动运行相关检查，未重复整组编辑器浏览器套件。没有改动用户数据；定位信息保留不表示已经验证具体 PDF 页码或附件区块的渲染跳转。URL 查询参数和复杂嵌套代码不在本轮验证范围内。
