# 研思录与 StarBridge MDN 最小接入契约

- 版本：V0.2，2026-10-03；修正首期范围、目标绑定、结果恢复和隐私边界。
- 状态：讨论稿 / 待双方评审；不是实现完成或真实流量授权。
- 本轮范围：研思录侧设计文档；MDN 仓库只读。无账户、资金、密钥、路由或生产操作。
- 前提：研思录软件永久免费；用户直接向 MDN 付费，研思录不收款、不维护钱包。
- 产品、接口、安全与验收责任人：由双方指定，本文不虚构具名批准。

## 1. 一个最小用户结果

用户用选中的笔记检查文章提纲，收到可核对的结构建议，并能回到对应提纲章节或依据笔记。

首个切片只做“提纲结构检查”：输入为章节标题、要点和所选笔记片段，沿用既有 `currentOutline.sections` 与检查类型。它不读取文章正文，不承诺检查段落论证或整篇文章。不会自动修改正文、保存关系或生成整本书。正文论证检查需另行定义段落定位、引用与输出契约，不能只更换模型后宣称支持；观点整理、关联建议也另行接入。

不配置 AI、断网、Key 无效或余额耗尽，都不能阻止本地编辑、搜索、关联、保存和导出。MDN 不成为笔记库所有权来源。

## 2. 产品和数据所有权

| 对象 | 权威来源 | 研思录行为 |
| --- | --- | --- |
| 笔记、依据、文章与用户修改 | 用户本地笔记库 | 读取所选内容；AI 结果待用户核对，不覆盖正文 |
| 账号、Project、Key、模型权限 | MDN | 用户在 MDN 开通；研思录保存受限凭据引用，不复制账号体系 |
| Usage、最终费用、余额与账单 | MDN | 不自行扣款；无获准价格/账单接口时不展示精确费用或余额 |
| 模型能力与兼容 Profile | MDN 版本化声明与双方验收 | 列表可见不等于能力满足，按任务筛选已验证模型 |
| 建议正确性和使用决定 | 用户核对；研思录负责输出校验 | 区分有效格式、来源有效和语义质量，不把格式通过当成结论正确 |

调用路径：研思录界面 -> 本机 API/执行器 -> MDN 公共 HTTPS 接口。不得新增研思录收费代理，也不得接入 MDN internal/operator API。

两个项目由关联团队开发，对外明确说明关系。软件免费和 MDN 服务收费分开表达；“比官方便宜”仅在相同模型、币种、计费维度和比较日期可核实后使用，不能成为通用保证。

## 3. 用户流程与凭据

1. 用户主动打开远程 AI 设置，前往经过确认的 MDN 官方控制台开通服务。
2. 在 MDN 创建研思录专用 Key；按最终支持的权限限制模型、调用与预算，不索取管理员凭据。
3. 回到研思录填写 Key、选择少量任务适配模型。连接测试明确可能收费，点击测试才发送合成短文本。
4. 正式任务开始前显示供应商、模型、提纲与所选笔记的实际发送预览；用户可返回删减材料，重新预览确认后再发送。未确认不发送，不能把连接测试当作上传授权。
5. 返回建议后能查看原文、忽略建议或手动修改。错误有下一步和可复制的 Request ID。

MDN 公共 API 从 Key 推导租户/Project；研思录不伪造或选择租户 header。研思录不实现 MDN 注册、支付或身份合并；MDN 当前自助开通是否获准需单独确认，不能用目标规格替代现有客户开通边界。

Key 的目标存储为操作系统凭据设施，业务配置只保存 SecretRef；实际跨平台存储实现须审查后才可声称达标。浏览器验收也不得将 Key 放进 localStorage、URL 或普通笔记库文件。Key 不进入备份、导出、截图、错误详情或日志。支持替换/清除，撤销权限由 MDN 执行。不能在客户端分发团队共享主 Key。

### 3.1 目标与授权绑定

- MDN 预设只允许双方确认的 HTTPS 服务源（scheme、host、有效 port）和公共 API Base path；URL 不允许 userinfo、query 或 fragment，不允许 internal/operator 路径。自定义供应商是独立配置，不能复用 MDN 凭据。
- 凭据引用绑定服务源、API Base path 和凭据代次。修改源或 Base path 后原绑定失效，必须重新选择/录入并确认凭据，不自动把旧 Key 发送至新地址。
- 首期所有带凭据 HTTP 请求禁止自动跟随重定向，同源重定向也停止并报告配置错误；不能先跟随再检查最终地址。TLS 验证失败停止，禁止绕过证书校验。
- 每次正式任务的发送确认绑定端点、模型、兼容 Profile、凭据代次与实际输入指纹。任一变化使确认失效；发送前再次校验。连接测试只授权合成测试文本。
- 运行中替换配置、清除 Key 或切库时取消旧本机请求并隔离晚到结果，不将请求重新绑定到新配置。取消不保证撤回已发送的内容或免除已发生费用。

## 4. 最小接口 Profile（候选）

| 项目 | 候选约定 | 实施前确认 |
| --- | --- | --- |
| 环境 | 配置独立的 MDN 测试 HTTPS Base URL；生产地址不猜测 | 官方地址、证书、开通方式、流量 Gate |
| 模型列表 | `GET /v1/models`，只显示当前 Key 获准模型 | 能力声明来源、版本、结构化输出/上下文边界 |
| 任务调用 | `POST /v1/chat/completions`，首期文本、非流式 | 已支持的 role、输出参数及 JSON schema 子集 |
| 鉴权 | `Authorization: Bearer <user-key>` | Key 范围、撤销与轮换语义 |
| 总超时 | `X-MDN-Request-Timeout-Ms`，与本机请求总预算绑定 | 获准上限；重试不能重置预算 |
| 幂等 | 每个明确的新操作创建稳定 `operationId` 与 `Idempotency-Key`；恢复不是新操作 | 服务端作用域、请求指纹、去重保留期与恢复能力 |
| 追溯 | 保存 `x-request-id`、兼容 Profile 和客户 LogicalModel | 成功、错误及无响应时的可用性 |
| 用量 | 可选客户安全 Usage/对账接口 | schema、finality、权限；unknown 不能当成零 |

不用 MDN Responses、SSE、工具执行、托管会话、联网检索或 embeddings 作为首期依赖。后续扩展须另验收，不宣称完整协议兼容。

研思录已有 OpenAI-compatible 请求构建与执行器，可作为适配入口，但当前字段不能默认都被 MDN 接受。建立固定请求 Profile，只发送双方已确认支持的字段；不支持的参数显式失败，不静默丢弃。JSON/schema 请求方式须按已验收能力选择，不把返回 JSON 文本等同于严格结构化输出能力。

## 5. 数据发送与结果校验

- 仅发送本次确认的提纲标题/要点、所选笔记片段、必要引用和任务说明，不自动附带整篇文章正文、未选笔记、图片、库路径或设备/联系人元数据，也不扫描或上传整库。
- 所选文字本身可能含姓名、联系方式、路径或其他敏感信息。首期不承诺自动识别和脱敏；预览显示实际发送文字，提示用户核对，支持返回删减或取消。返回修改后必须重建预览与发送确认，不能在后台静默改写材料。材料内仍保留的敏感文字会随请求发送，这一点必须明确说明。
- 超过上下文限制时先提示缩小范围；不静默截掉关键证据。数据留存、处理区域和转交实际模型服务方的规则须由 MDN 明确。
- 提纲与笔记中的指令当作材料，不能授权模型调用工具、改变供应商或读取更多笔记。
- 输出沿用研思录既有建议结构和校验器：类型合法、引用 ID 在发送集合内、引用原文确实存在。编造 ID/引文或非法结构不能成为可采纳建议。
- 来源匹配只是必要条件，不代表语义正确；误判、遗漏与无根据建议另行评测。没有发现问题与生成失败必须区分。
- 输入快照仅在本机任务内存中用于校验；持久化恢复记录仅含第 6.1 节的最小元数据，不持久化完整请求包。生成期间修改提纲、依据笔记或切库后，旧结果不得作为当前建议采纳。首次结果与恢复结果均须匹配输入指纹、章节位置及发送时引用片段，不能拿新内容校验旧结果。

## 6. 失败、取消与费用

| 情况 | 用户反馈与动作 |
| --- | --- |
| Key 无效、撤销、禁用或过期 | 修改/重新创建 Key；不自动重复调用 |
| `model_not_allowed` | 选择获准模型；不自动换模型 |
| `insufficient_balance` | 前往 MDN 查看账单/补充额度；不弹出研思录充值 |
| `unsupported_parameter` / 上下文超限 | 参数或材料范围不支持；不通过删除约束偷偷重试 |
| `rate_limit_exceeded` | 展示等待提示，允许用户稍后重试；首期不后台自动收费重试 |
| 超时、断网或 5xx | 结果可能不明，保留原稿；不能声称未执行或未收费 |
| `request_in_progress` / `request_already_processed` | 按已确认幂等契约核查，不把重复执行当成普通重试 |
| `idempotency_conflict` | 客户端请求状态异常，停止提交，不生成新键自动绕过 |
| 用户取消 | 中止本机等待并传播下游取消；已发生的调用仍可能收费 |
| 非法结果或无效引用 | 建议不可采纳；不承诺因此不收费，也不编造替代建议 |

首期执行器每次明确操作最多一个客户端生成请求，不启用后台自动重试。手动再次调用提示可能再产生费用；重复按钮点击去重。结果不明时不能无提示改用新幂等键。MDN 内部 Attempt/Fallback 与客户端 Request 分开，费用事实由 MDN 管理。

### 6.1 结果不明与重开恢复

发送前，先在本机应用私有存储写入操作记录，成功落地后才可 POST。不能写入记录则停止调用。记录含 `operationId`、稳定幂等键、服务源与 endpoint、LogicalModel/Profile、凭据代次引用、库/写作对象标识、输入版本指纹、创建时间、状态，以及收到后补充的 MDN Request ID；不含 Key、材料正文或输出。不得进入笔记库备份、普通日志或默认诊断导出。

候选状态：`prepared` -> `dispatching` -> `completed` / `failed_confirmed` / `unresolved`。`completed` 只表示本机收到并校验了结果，不代表账单已结算；`failed_confirmed` 也不代表免费。发送前先标记 `dispatching`；崩溃发生在标记之后，即便请求可能尚未发出，重开也按 `unresolved` 处理，不能猜测未执行。

| 恢复情况 | 首期行为 |
| --- | --- |
| 刷新或重开发现 `dispatching` / `unresolved` | 恢复“结果未确认”，不恢复 POST、不创建新幂等键、不重新上传材料 |
| 已有 Request ID 且有获准公共查询 | 只做只读查询；若只返回 Usage，不能伪造或声称取回建议正文 |
| 没有 Request ID | 不假定已有按幂等键查询接口。无获准查询路径则保留未确认状态，提示到 MDN 控制台核对；首期不以再次 POST 作为查询 |
| MDN 已完成但不缓存输出 | 提示“调用已处理，但未取回建议”，保留原稿；账单由 MDN 核对，不能重新执行来冒充结果恢复 |
| 状态仍进行中、查询失败或查无记录 | 不等同于未执行/未收费；保持未确认，提供手工核对信息，不自动轮询或重新生成 |
| 用户明确决定再次付费生成 | 告知上次可能已收费、新操作可能再次收费，重新确认当前材料后创建新操作和新键；旧记录仍独立保留 |

无法查询不阻止本地工作，但该操作的自动恢复和重试处于停止状态。移除 Key 不抹除未确认记录；不能用另一凭据代次自动查询旧操作，恢复查询须重新核实原 MDN Project/权限，未确认则转人工核对。

记录的本机保留期与 MDN 幂等去重期必须在双方实现 Profile 中给出明确数值并验收；当前未确定，因此不得宣称跨重开自动恢复已完成。首期不自动删除未确认记录、不跨过未知去重期限重放 POST。用户可明确删除记录，但需提示这会失去本机核查线索，且不取消服务端调用或账单；删除后也不能自动重试旧操作。此处仍无自动收费重试。

`GET /v1/usage` 不是钱包或价目表。未有获准报价接口时显示“按 MDN 账户规则计费，实际费用以 MDN 账单为准”，不显示虚构金额。以后估价须标明模型、价格版本、币种、估算范围及未知项，不能宣称客户端输出 token 限制等于严格金额上限。

## 7. 双方验收清单

下列全部为待执行，不是当前通过证据。

| ID | 验收结果 | 证据 |
| --- | --- | --- |
| C01 | 无远程配置仍能完成整理、写作和导出 | 本地流程及实际输出文件 |
| C02 | 有效 Key、获准模型与合法请求可返回建议 | 合成测试请求和 Request ID，原稿 hash 不变 |

| C04 | 无效 ID、引文、结构不能成为当前可采纳结果 | 受控响应与真实校验断言 |
| C05 | 余额不足、429、5xx、断网和超时反馈准确，不重复提交 | 请求计数和可见错误；不以 UI 断言收费事实 |
| C06 | 取消、编辑、切库或配置变化后旧结果不能作用于新内容 | 受控慢请求、授权失效和文件核对 |
| C07 | 双击、崩溃、刷新、无 Request ID 和无缓存输出不触发重复生成 | 操作记录与 MDN Request/执行次数；无查询能力时安全停止；新付费操作须明确确认 |
| C08 | 凭据替换、清除、权限撤销与日志/备份排除成立 | 合成 Key；不得把真实 Key 写入测试产物 |
| C09 | 模型质量达到双方预先约定门槛 | 同一组中文真实任务，比较误判、遗漏、引用、耗时和成本 |
| C10 | 预览与实际发送内容一致，修改后重新确认 | 合成敏感文字；未选内容和系统元数据不附带，不虚构自动脱敏 |

C09 的样本、门槛和模型/Profile 版本由产品与验收人确认后再测试，不在看完结果后改阈值。包括无问题提纲、真正重复、证据缺口、合理分歧与范围限定，不能只测“你好”或把正文质量算作提纲验收。价格、余额与安全权限的正式验收不能用 Mock 证明。

执行顺序：文档评审 -> 合成契约测试 -> 获准测试环境与有限预算的真实模型比较 -> 用户验收 -> 独立正式接入批准。当前仅完成第一步的讨论稿；相关 MDN B0/F0/F1/F2 与真实客户/资金 Gate 必须按项目规则核实，不能因同一团队开发而默认获准。

## 8. 实施前待确认

1. MDN 可供研思录使用的测试地址、客户开通路径、支持的协议 Profile 和模型能力证据。
2. 专用 Key 的权限/预算范围，以及测试凭据安全交付方式；不通过聊天发送 Key。
3. 数据处理区域、留存与实际模型服务方说明；对外关联产品关系表述。
4. 首个提纲结构检查任务的模型、质量门槛和获准测试预算；正文论证检查另定范围，不混用验收。
5. 幂等/取消/结果不明的实际能力、操作记录与去重保留期限及公共查询范围；无 Request ID 查询、输出缓存均不能假定存在。报价与账单入口在未确认前不接入。
6. MDN 允许服务源/API path、凭据绑定与配置代次、发送预览及授权失效规则；确认后才进入实现。

回退方式：关闭 MDN 远程配置并清除本机凭据引用，继续本地工作；不撤销已完成的用户修改，不回滚或重写 MDN 账务。
