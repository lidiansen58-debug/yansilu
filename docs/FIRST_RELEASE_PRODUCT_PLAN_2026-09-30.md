# 研思录首个正式 Release 产品方案

更新：2026-09-30
实现基线：`main / 4e781c1f`，当前版本 `0.1.1-beta.1`。
状态：设计与任务方案已建立，产品改动尚未实施。首版范围暂按“文章闭环 + 基础书稿组织”制定，若产品负责人要求完整书籍制作，应重新估算和冻结范围。

## 1. 本次要交付的用户结果

研思录帮助用户把已有笔记变成清晰观点和写作结构。
对外保持：**让笔记生长为思想**；**永久笔记 · 知识网络 · 原创写作**。

首版必须让用户独立完成：

`记下一条内容 -> 用自己的话说明理解 -> 留下可追溯的观点 -> 找到相关观点 -> 围绕问题组织提纲 -> 写正文 -> 导出分享`

知识网络的复利来自旧观点能被找回、用于新的问题和作品，并能被新证据修正。数量、连线或 AI 输出本身不能证明用户掌握了知识。

首次激活仍定义为“形成首条判断并看到可追溯脚手架”，不是创建笔记库或导入 Demo。文章导出是后续作品成果，不替代首次激活指标。

## 3. 界面改进方案

### 首页：继续一件事

- 空库主动作“记一条”，导入和练习为次级选择。
- 有内容时显示一个具体对象和动作，例如“继续整理：读书随笔”；有未完成文章时提供“继续写这篇文章”，不要总把用户送回积累笔记。
- 剩余事项按需展开，避免数量面板、AI 状态、方法介绍占据首屏。
- 首页要反映磁盘中的实际工作进度；统计和推荐错误也属于待验证问题。

### 笔记：先写，再整理

- 捕捉阶段只要求正文，随时保存。标签、目录和关联不是首次保存门槛。
- 整理阶段围绕“我想说明什么”“依据是什么”组织界面。问题、反例、立场变化可展开，不强迫每条笔记填写同样字段。
- 保存后显示已形成的当前观点及来源入口，再给一个合适的下一步。
- 原创性检查表达为来源相似度等辅助检查；通过不等于内容正确或得到法律意义上的原创认证。
- “归类与移动”保留随笔、文献笔记、永久笔记用途，用简短说明让用户知道当前类型由所在目录决定；操作前说明目标类型与位置，不让分类规则继续成为黑盒。

### 知识网络：看懂关系，拿去使用

- 从当前笔记的真实关系开始，可搜索目标、选择五种常用关系、写一句影响或理由。
- 正文自动链接与手动外部关联都是正式关系，不给前者更低权重；相同关系不重复计数。
- 点笔记可以阅读，点关系可以解释。支持、反驳、条件、例子帮助用户比较判断。
- 选择能回答同一问题的笔记进入主题或写作，不能只停在可视化。
- 先验证现有图谱交互；首版不重写布局、扩充关系本体或编造演示连线。

### 写作：得到一份作品

- 沿用主题、提纲、草稿三个 Tab。主题只要求题目、想回答的问题和相关笔记。
- 提纲能调整章节顺序、标题和用途；每节能回到使用的真实笔记。
- 草稿可保存、重开、继续写。保存与导出分别有清楚反馈。
- 草稿页提供“复制正文”和“导出文章”，保留提纲导出作为次级操作。
- 书稿入口复用相同写作流程，增加可切换章节目录，不把所有历史书稿面板一次性露出。
- 首版书稿最低结果是三章内容、章节顺序、笔记依据和完整 Markdown 导出；编辑排版、EPUB、印刷级 PDF 后续处理。

### 统一视觉与反馈

- 以现有应用样式为基础统一字体、字号、间距、控件高度和标题层级，不重建整套主题。
- 编辑正文是主要区域；辅助栏可折叠。页面段落不再层层套卡片。
- 主操作有稳定位置；工具图标带名称提示；低频操作放入“更多”。
- 成功、保存中、失败和结果待核查区别明确，不能只变按钮颜色。
- 检查 1366×768、1920×1080 及当前桌面最小窗口；窄屏只保证已有入口可使用，本轮不重构手机产品。

## 4. 帮助用户用好

### 第一次：实际做一遍

基于现有 Demo 提供一条短练习：选一条材料、亲手写一句理解、保存当前观点、查看依据、建立一条有理由的关联、用两三条笔记得到小提纲。
练习入口直接到操作对象，按钮完成后检查真实数据再标记进度；支持跳过、退出和返回继续，不覆盖用户已有内容。
首屏不要求阅读 14 条永久笔记和全部关系。完整示例保留，按需查看。

### 每次：得到具体帮助

就近给一句动作提示或一个例子，不再添加长期展开的教学面板。
例如关系理由：“这条记录说明了观点在哪种情况下成立。”
写作受阻时指出具体笔记及缺失项，点击能直接处理；不显示 `draft`、内部 ID 或不可见按钮的指引。

### 长期：检验能否复用

用户回到旧问题时，能通过正文搜索找到笔记，读懂自己的判断，说明依据和限制，并用于一篇新文章。
首版通过新用户任务和隔几天后的续写验证这一点。暂不增加间隔重复、考试或自动知识掌握评分；产品不能以保存或点击替用户证明理解。

### AI：辅助可选

基础记录、整理、关联、写作和导出必须无需远程 API 就能完成。
已有 AI 可辅助整理、建议关系或检查结构；建议需用户确认。远程调用前说明范围和第三方费用。
模型不可用时仍能手动完成。首版不把语义搜索、全库自动分析或一键生成整本书作为承诺。

## 5. 发布边界

首个正式 Release 支持 Windows x64 和 macOS Universal。macOS 必须分别在 Intel、Apple Silicon 实机完成安装与主链路验收。
软件本身免费，数据在本地，无账号要求。第三方模型费用另行说明。

正式版号在候选版验证时统一决定，不继续覆盖 `0.1.1-beta.1`；不要把候选版放到 stable 自动更新地址。
Windows 代码签名、macOS 签名公证与 Tauri 更新签名是不同的发布事项，需按发布清单逐项核实。

首版后再推进：完整书籍自动生成、专业排版、语义搜索、分类存储迁移、账号/云同步、手机重构、团队协作。
已有功能若发现数据损坏或安全阻塞仍必须处理，不因延期而忽略。

## 6. Release 完成标准

全部条件通过才可称为首个正式 Release：

1. 临时库中完成记录、观点、依据、关系、主题、提纲、草稿、文章导出的连续实测，导出包含正文而非只有提纲。
2. 一个三章书稿可保存、重开、调整顺序并完整导出；章节依据可回到真实笔记。
3. 保存、切库、导入、移动和更新的故障不丢数据，不显示假成功；备份可恢复到新库。
4. 3 位不熟悉卡片笔记方法的用户中，至少 2 位在无口头引导下完成短练习及文章导出；全部能保存第一条记录。记录实际耗时和卡住位置，不以测试代替用户理解。
5. Windows、macOS 两种芯片完成最终安装包验收；帮助离线可读，安装路径和程序入口明确。
6. 发布版本字段一致，安装包校验、平台签名、更新签名、旧版升级和回退证据完整，官网说明与已验收能力一致。

上述人数是首版小样本门槛，不代表普遍易用性结论。未通过项记录到任务表，不能只打包后宣布完成。
