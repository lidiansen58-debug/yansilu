# 核心流程优化：从记录到写作

本轮围绕“记录、重述、关联，让笔记生长为思想”，修正主流程中的错误提示和断点。保留现有页面与视觉体系，不增加新的工作台或帮助面板。

## 设计取舍

- 首页默认只推荐一个下一步，先说明要做什么，再展示要处理的笔记。其他步骤按需展开。
- “已完成”“可以写作”必须由实际内容和确认状态决定，不能由模板标题或占位文字决定。
- 主题默认显示三个，展开后能搜索整个当前主题范围。继续草稿要回到已有项目，不另建一份。
- 用户换页、换库或选择其他项目后，旧请求不得提交主题、切换写作步骤或覆盖当前状态提示。

## 已实现

1. 首页写作推荐与写作入口共用永久笔记资格判断。观点必须包含已确认的一句话判断和三句摘要；已转成永久笔记的随笔、文献记录不再反复推荐处理。
2. 完成度检查忽略空的“边界 / 反例”标题、默认问题、注释和代码示例；全部完成后不再提示重复补关系理由。
3. 主题库增加展开、收起和搜索，保留输入焦点。接口支持分页，服务端同时间、同标题以 ID 稳定排序，前端取消原有三条显示和十二条读取造成的不可达状态。
4. 首页写作入口和主题选择器检查请求归属；笔记加载后再次检查。导航轮次可识别“离开再返回同一页”，仅捕获轮次不会取消调用方自己的跳转。当前操作自身添加材料不会被误判成外部项目变更。加载期间新增的未保存草稿仍会阻止切换主题。
5. 首页展开控件使用原生按钮及 `aria-expanded`、`aria-controls`，对应内容为具名区域。

## 代码组织

| 模块 | 职责 |
| --- | --- |
| `note-readiness-signals.js` | 共享内容完成度、观点确认和写作资格判断 |
| `today-writing-navigation.js` | 首页进入主题、写作的编排与过期请求保护 |
| `writing-theme-selection-request.js` | 读取并加载主题笔记，在提交前验证请求归属 |
| `writing-theme-library.js` | 主题列表展开、搜索及控件状态 |
| `writing-theme-index-loader.js` | 按目录分页读取、换库保护及旧接口无进展检测 |

`prototype-app.js` 仅保留依赖装配，相关规则移入上述局部模块。没有数据库迁移，也没有改动既有草稿正文和保存协议。

## 验证与边界

独立 review 确认的四个问题均已修复：标点结尾的空边界标签、添加材料导致自身跳转失效、旧主题响应晚到后提交状态，以及离开再返回写作后仍提交旧主题。修复后独立 review 未发现 P1/P2。
