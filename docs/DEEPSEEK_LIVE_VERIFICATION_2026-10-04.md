# DeepSeek 真实 API 验证

2026-10-04，源码分支 `fix/deepseek-remote-setup`。使用 `deepseek-flash` 和临时笔记库，仅发送两条人工编写的示例笔记；测试后已删除临时库。密钥通过进程环境使用，没有写入源码或报告。

## 真实结果

| 功能 | 耗时 | 结果 |
| --- | ---: | --- |
| 保存服务配置并重新读取 | 257 ms | 模型映射恢复，返回值无密钥正文 |
| 连接测试，3 次 | 836 / 602 / 892 ms | 均成功，每次输出 2 tokens |
| 写作分析 | 2420 ms | 返回 5 个待审阅产物，输出 371 tokens |
| 来源观点提炼 | 1648 ms | 返回可编辑观点草稿，输出 152 tokens |
| 无明显问题的提纲检查 | 1054 ms | 返回空检查结果，输出 5 tokens |
| 关联审阅 | 1117 ms | 返回拒绝建议，不自动建立关联 |
| 相同关联重复审阅 | 215 ms | 命中缓存 |
| 原笔记读回 | 240 ms | 两条笔记均未改写 |

同一连接提示的默认思考模式另测一次：902 ms，输出 22 tokens，其中 19 tokens 为思考内容。优化后的三次测试每次仅生成 2 tokens；在此次简单任务中，额外思考没有提供必要的功能收益。样本量小、网络条件有波动，不能将耗时差解释为普遍的速度提升。

正式完成的功能检查均通过。调试脚本初版还修正了两个测试夹具问题：远程模型映射不接受本地专用层级；关联扫描与审阅必须使用一致的筛选阈值。这些请求在调用模型前被应用拒绝，随后已修正脚本并重新完成整套验证。

## 功能设计结论

- 日常连接测试、观点提炼、简短写作检查和关联审阅可先使用 Flash。
- 连接测试保持非思考模式、256 tokens 上限和 30 秒等待上限。
- 结构化任务使用 JSON 输出，并保留任务的结构要求与来源验证；生成结果仍需用户审阅。
- 相同关联重复请求使用缓存；修改笔记或服务配置后应重新审阅。
- 本次没有评估长文、复杂推理或 Pro 的质量，不据此取消后续选择更强模型的能力。

平台余额接口在本轮采样前后均返回 99.92 元。该数值只有两位小数且可能有结算延迟，不能视为本轮免费。应用返回的 `estimatedCost: 0` 也是当前适配层的占位值，不是实际扣费。真实费用应以平台账单为准。

## 重现

将专用测试 Key 放入进程环境变量 `DEEPSEEK_API_KEY` 后执行：

```powershell
node scripts/verify-deepseek-remote-ai.mjs
```

可用 `DEEPSEEK_TEST_MODEL` 指定模型。脚本会产生少量真实 API 用量，先测试草稿连接，成功后保存配置，再测试两次保存后的连接、写作、提炼、提纲、关联及缓存，最后对比默认思考连接测试。默认使用 Flash；不自动运行高并发或长期测试。

后续复查已补齐失败处理：必需的连接或配置检查失败时立即结束，不执行后续付费调用；单个独立功能失败仍记录结果，便于检查其余功能。记录器在成功和失败输出中均过滤密钥。该脚本调整由本地回归验证，上表保留之前真实联调的历史结果，不代表已重新执行付费测试。

不含密钥的详细运行报告保存在 Git 忽略目录 `output/remote-ai/deepseek-live-report.json`。脚本语法检查和 `git diff --check` 通过，之前的模拟服务和浏览器回归见 [远程 AI 验证](REMOTE_AI_VERIFICATION_2026-10-04.md)。
