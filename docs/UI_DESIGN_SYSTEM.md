# 主流程界面规范

更新：2026-10-09。写作页作为样板，规范已应用到首页、笔记与关联、写作、图谱、主题建议及设置的主流程。低频专业工具仍沿用各自布局。

## 视觉基础

设计面向日常记录、阅读和写作：内容优先，白色工作面，青绿色主操作，清晰的字体和间距。阴影只用于弹窗与菜单，避免每层内容都套卡片。

共享变量由 `apps/web/src/ui-design-system.css` 定义。功能样式负责布局，优先复用变量，不另设按钮尺寸、字体或圆角。

| 项目 | 规范 |
| --- | --- |
| 界面字体 | Segoe UI / PingFang SC / Microsoft YaHei / sans-serif |
| 正文 | 写作正文 16px，行高 1.85；手机输入至少 16px |
| 控件文字 | 14px，600 字重 |
| 控件高度 | 桌面至少 40px；700px 以下至少 44px |
| 控件圆角 | 8px |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32px |
| 主色 | `--ui-brand`，#0f766e |
| 正文和次级文字 | `--ui-text` / `--ui-text-muted` |
| 边框和工作面 | `--ui-border` / `--ui-surface` |
| 错误 | `--ui-danger`，同时显示文字，不仅改变颜色 |
| 焦点 | 2px 主色轮廓，保留键盘操作与输入法行为 |

按钮使用已有 `.mini-btn`，主操作加 `.primary`，低优先级操作加 `.is-ghost`，危险操作加 `.is-danger`。图标按钮同时提供可访问名称，手机点击区域至少 44px。章节工具等低频操作放进菜单，保留取消与退出路径。

## 信息与交互

- 每页保留一个主操作。相同任务使用相同名称，不因保存状态更换操作含义。
- 页面标题说明当前对象。桌面目录显示当前章节，窄屏使用章节选择器；正文标题属于内容，不再额外复制章节名为面板标题。
- 写作默认使用正文编辑，Markdown 源码作为可切换的编辑方式。笔记引用显示名称，保存与导出保留引用身份。
- 重名引用要求明确目标，不按模糊相似名称跳转。慢请求返回时若已继续输入、换章节或换笔记库，取消旧跳转。
- 输入说明放在对应字段附近；能靠标签表达的内容不再写一段说明。
- 保存状态与操作分开：“有未保存的修改”“已保存”是状态；“保存”“重试保存”是操作。
- “已保存”只对应当前输入。保存期间继续输入，最新修改仍显示未保存。
- 失败保留输入，提供明确重试动作。未确认的保存结果不得显示成功。
- 菜单支持 Escape 和点击外部关闭；关闭后返回入口。打开弹窗时，弹窗获得焦点，取消后返回可见入口。
- 提示不能遮挡下一步操作。写作页的全局提示占用独立布局行。
- 保存观点后，正文同时保留已确认观点与用户继续输入的段落，光标跟随原输入位置。用于识别观点区块的内部标记保存在 Markdown 中，正文和阅读预览不显示；用户写进代码示例中的同名文字正常显示。
- 后台加载项目列表时，不重建正在编辑的主题建议表单；保留输入、焦点及输入法状态。主动刷新建议或建议范围变化时正常更新。
- 窄屏允许合理换行，避免裁切按钮；不能仅靠“页面无横向滚动”认定布局通过。

## 分阶段迁移

1. **共享控件与写作样板（已落实）**：统一按钮、表单和焦点规范；清理重复章节标题；折叠目录工具；验证保存、失败恢复和真实导出。
2. **写作编辑体验（已落实样板）**：默认正文编辑，可切换 Markdown；引用显示名称，支持打开来源；桌面章节目录替代下拉框，手机保留下拉切换；保存沿用原有正文与恢复机制。
3. **笔记与关联（已落实）**：入口统一为“观点与关联”，字段使用“当前观点”“最初的问题”；确认观点时保留正文新输入与光标，隐藏内部标记；验证随笔、文献转换及关联编辑的失败恢复。
4. **首页、图谱、主题与设置（已落实）**：首页只显示一次路径和统计，清理重复步骤说明；图谱采用一致的任务标签与控件；主题建议默认收起推荐依据、相关笔记的逐条理由，显示名称而非内部编号，字段具有明确标签；设置沿用共享控件。手机保留全部操作。

## 验收方式

图谱工作面使用共享浅色背景、深色笔记名称和语义关联线，移除星点、光晕及节点脉动。分组区域保留点击与键盘选择；选中节点用清晰轮廓表达。缩放预设直接显示“全览”“放大”“细节”，不用悬停才显示名称；移除不能操作的拖动按钮，首次使用提示保留滚轮缩放和拖动说明。窄屏工具栏允许换行，保留展开、缩小、放大和三个缩放预设。样式位于 `apps/web/src/graph-workspace.css`，不改图谱布局或关联保存逻辑。

使用真实 API 与独立临时笔记库。检查 1366、390、320px 的实际截图、控件边界、键盘焦点和主要操作是否可点击；保存与导出核对实际文件。功能测试通过与视觉审查通过分别记录，已有 main 失败不得记为本轮通过。

写作样板的正式检查入口为 `tests/e2e/prototype-design-system.test.mjs`，包含正文输入、格式操作、模式切换、快捷键保存、失败重试、保存期间继续输入与引用跳转。完整用户路径为 `tests/e2e/prototype-mainline-task-acceptance.test.mjs`，长正文与整稿导出为 `tests/e2e/prototype-writing-long-work-ux.test.mjs`。运行产物保存在被忽略的 `output/` 中。

跨页面检查为 `tests/e2e/prototype-main-flow-design.test.mjs`：检查 1366、390、375、320px 的首页、图谱三个任务、主题建议及设置的实际控件边界与触控尺寸；图谱另验 844×390 横屏及减少动态效果设置。延迟项目列表响应，确认主题输入框保持挂载和焦点。主题建议保存核对真实 API；完整主流程核对文章与各章节实际导出文件。
