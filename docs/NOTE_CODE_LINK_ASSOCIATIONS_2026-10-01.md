# 代码引用与自动关联的解析边界

分支：`fix/note-link-selection`。接续编辑器代码示例保护，将规则扩展到服务端自动关联、导入和前端笔记元数据。

## 行为

- 普通行内代码、围栏代码、缩进代码及转义的 `\[[…]]` 不再计入正文笔记引用。真实正文引用、别名、标题/区块定位和嵌入引用继续识别。
- 笔记创建和保存、文件重新同步、导入确认统一使用 Markdown 模块的链接解析。代码中的引用也不再污染前端 `note.links` 或导入预览的目标列表。
- 保存或重新同步会清除旧的 `markdown_wikilink` 错误自动关联，保留独立建立的关系，包括同一目标之间的支持关系。最后一处真实正文引用移除后，代码中剩余的示例不会继续维持自动关联。
- 代码边界源文件集中在 `packages/markdown-engine/src/markdown-code-context.mjs`；`build:toastui` 以 UTF-8 生成前端同名模块，单元测试检查两份内容一致，避免服务端与浏览器规则漂移。

没有启动全笔记库迁移或修改用户数据。旧关联在笔记保存或调用现有目录同步流程时修正。本轮未调整重命名时的引用文本重写；嵌套列表/引用代码块、HTML 代码区域、真实系统输入法及长文档性能未验证。

## 验证

- 651 项相关单元测试通过：编辑器/笔记/关系 570 项，Markdown/目录/导入服务 63 项，演示引用数据 18 项。
- 28 项相关浏览器用例通过：正文链接 17 项、编辑往返及草稿 5 项、关系安全 2 项、旧入口 4 项。
- 目录生命周期测试覆盖创建、保存、磁盘文件修改后重新同步、重复同步、模拟旧错误自动关联，以及同目标独立关系的 ID/类型/说明保留。
- 真实导入服务测试检查预览和确认导入后只建立正文关联，代码目标没有反向关联。
- 加强源码和富文本浏览器用例：同一目标的正文引用与代码示例并存，移除正文引用后自动关联消失、独立支持关系保留，前端引用元数据为空，刷新后代码原文完整。
- ToastUI 构建成功，编码检查无新增问题，`git diff --check` 通过。测试使用临时笔记库。
