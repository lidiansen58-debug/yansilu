# 编辑器代码示例中的链接边界

分支：`fix/note-link-selection`，基于此前正文链接编辑、移除和选区修复。

## 行为

- 编辑器的链接修改、移除和自动补全不再把普通行内代码、反引号/波浪号围栏代码、缩进代码内的 `[[…]]` 作为正文链接入口。手动点击链接工具时提示在代码外插入，保留选区内文字。
- 转义的 `\[[…]]` 和 `\[[` 输入不作为现有链接或自动补全触发器；双反斜杠之后的真实链接仍可识别。
- ToastUI 加载 Markdown 时，代码中的链接和标签文字不再被替换成内部 widget。修正了这些包装污染代码原文并影响后续光标定位的问题；用户自己写出的 `$$widget0 [[字面示例]]$$` 仍保留。
- 独立的代码范围模块同时用于链接识别和编辑正文的 widget 还原，减少两处边界规则不一致。大编辑器文件只增加入口判断。

构建脚本对 ToastUI 3.2.2 的 Markdown 模型加载入口使用有限替换，调用独立段落构建模块。预期入口结构不匹配时构建明确失败，不能静默跳过；升级 ToastUI 必须重新验证。源码与生成 bundle 同步。

## 验证

- 570 项相关单元测试通过。新增 13 项检查代码范围、未闭合围栏末尾、正确的关闭标记、多反引号、多行行内代码、转义、代码与正文的交界，以及 CRLF 段落中真实 widget 字面量。
- 28 项相关浏览器用例通过：正文链接 17 项、编辑往返/草稿 5 项、关系安全 2 项、旧入口 4 项。
- 新增源码和富文本用例验证代码中的工具栏操作不改文、不打开链接窗口；已有正文链接窗口会关闭，焦点返回编辑器。代码内键盘输入 `[[` 不弹出补全，代码外的真实链接仍可移除；保存刷新后两处代码引用与字面 widget 内容保持完整。关闭旧窗口的加强用例另行复验通过。
- ToastUI 构建、编码检查和 `git diff --check` 通过。使用临时笔记库，没有改动用户数据。

本轮范围是编辑器识别与代码原文保护，未调整服务端自动关联、导入及重命名所用的链接解析。服务端当前仍使用正则提取代码中的引用，需要后续单独统一边界规则；本报告不表示该自动关联行为已经修复。嵌套列表/引用中的代码块、真实系统输入法和长文档性能未验证。

后续已统一服务端自动关联、导入和前端引用元数据的边界，详见 [代码引用与自动关联的解析边界](NOTE_CODE_LINK_ASSOCIATIONS_2026-10-01.md)。重命名时的正文重写不在该后续改动范围内。
